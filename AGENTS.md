# Working on this site

This project was generated by [site-forge](https://github.com/jonesruskin/site-forge). All code
is yours; the `site` CLI helps add, update and remove modules without a lock-in.

## Commands

| Command              | What it does                                                         |
| -------------------- | -------------------------------------------------------------------- |
| `pnpm dev`           | Development server (works without API keys: email, payments, database fall back to local stand-ins) |
| `pnpm build`         | Production build                                                     |
| `pnpm typecheck`     | Next.js route types + `tsc`                                          |
| `pnpm lint`          | ESLint (includes React Compiler and accessibility rules)             |
| `pnpm env:check`     | Validate environment variables exactly as production will            |
| `pnpm site add <x>`  | Add a module, `section:<name>` or `ui:<name>` from the registry      |
| `pnpm site remove <x>` | Remove one (files you edited are kept)                             |
| `pnpm site update`   | Take registry updates; `pnpm site diff [x]` shows them first        |
| `pnpm site doctor`   | Health check: generated files, deps, env vars, secrets in git        |
| `pnpm site sync`     | Regenerate `src/generated/*`, `src/env.ts`, `.env.example`           |
| `pnpm site theme <name>` | Switch to another theme; dial flags adjust the current one      |

## Where things live

- `site.config.ts`: name, URL, nav, and one block per module (`billing`, `blog`, …). Edit
  freely; the CLI updates it with an AST codemod.
- `src/styles/theme.css`: design tokens driven by a handful of dials (hue, radius, density,
  motion, type scale …). Change dials before changing components.
- `src/app`: routes. `(site)` has the header/footer shell; `(app)` is the signed-in area.
- `src/components/ui` (primitives) and `src/components/sections` (page sections): props in,
  markup out, no data fetching.
- `src/lib/<module>`: each module's logic. Its documentation is in `.site/modules/<module>.md`.
- `content/`: MDX and JSON content (posts, docs, projects, FAQ …).

## Rules

- **Never edit `src/generated/*` or `src/env.ts`** — they're rebuilt by `pnpm site sync`.
  Module integrations (sitemap entries, auth plugins, dashboard widgets, webhooks …) are wired
  through these generated "slots".
- **Style with semantic tokens only**: `bg-background`, `text-muted-foreground`,
  `border-border`, `bg-primary` … No palette colors (`bg-blue-500`), no hex values, no `dark:`
  color overrides (tokens already switch), no font names in classes.
- **Environment variables**: declare them in the module's fragment in `src/env/`, document
  them in `.env.example`, read them through the exported `…Env` object — never `process.env`
  directly in app code. `NEXT_PUBLIC_*` values are public.
- **Database** (if installed): tables in `src/db/schema/*.ts` with explicit snake_case column
  names; `pnpm db:generate` → commit the SQL → `pnpm db:migrate` on deploy.
- Forms use server actions + `useActionState`, validated with Zod on the server.
- Keep pages accessible: labelled controls, visible focus, one `h1` per page.
