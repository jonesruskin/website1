REST API

The public card endpoint for building your own card, and the key-authenticated endpoints for your tools and stats.

There are two kinds of endpoint:

  • The card endpoint is public. It uses your public site key (bk_…) and is what the embed calls. Use it to build your own card.
  • The account endpoints under /api/v1 are private. They use an API key (sk_…) and act as your account.

Get a card

ParameterRequiredDescription
keyyesThe public site key of the host tool, the one where the success moment happens.
ctxnoThe artifact this moment produced, such as pdf. See inputs and outputs.

200: a card

The values above are placeholders showing the shape.

FieldMeaning
card.titleThe headline of the card.
card.bodyOne line of supporting text.
card.ctaThe button label.
card.toolThe tool being recommended: its name and the host of its website.
card.viaLabels of the artifacts that connect the two tools, for example ["PDF"].
card.hrefA signed /r/<token> link. Always link to this, never to the tool directly.
badgetrue when the card should show the "passed by Baton" mark (hidden on paid plans).
poweredByWhere that attribution points.

204: no match

When nothing fits the journey, the endpoint answers 204 No Content with an empty body. Show nothing, or something of your own. This is the same case where baton.pass() resolves to false.

Other statuses

StatusMeaning
400The key is missing or malformed.
404No active tool has that key (unknown, deleted or paused).
429More than 60 requests a minute from one address. See Retry-After.

Clicks

card.href is a signed redirect. It checks the signature, applies the fairness rules, moves credits if the click qualifies, then sends the visitor to the tool with ?ref=baton added. Linking anywhere else means the click isn't counted and the credit isn't earned.

Building your own card

If you render the card yourself, show the Baton attribution (badge and poweredBy) unless your plan lets you hide it, and don't cache responses for long: a card is chosen for the moment it is requested.

Account endpoints

These are authenticated with an API key you create at Settings, API keys. The key is shown once when you create it and only its hash is stored, so copy it straight away.

EndpointScopeWhat it returns
GET /api/v1/toolsreadThe tools on your account, with credits and site keys. Studio plan.
GET /api/v1/statsreadCredits, passes sent and received, cards shown, and a daily series (?days=, clamped by plan). Studio plan.
GET /api/v1/mereadThe account the key belongs to. Every plan.

A key has scopes. read reads your account data and write creates and changes it. A request outside a key's scopes is refused with 403.

Response shape

Errors

Errors are RFC 9457 application/problem+json documents:

StatusMeaning
400The body isn't valid JSON.
422The query or body failed validation.
401No key, or a key that isn't valid.
403The key lacks the scope, or the endpoint needs Studio.
404The thing you asked for doesn't exist.
429You have hit the rate limit.

Rate limits

Each key gets 60 requests per minute. Responses carry standard RateLimit-* headers, and a 429 includes Retry-After with the number of seconds to wait.

Keep keys server-side

API keys act as you. Never put one in browser code. The site key (bk_…) is the only key that belongs in a page.
