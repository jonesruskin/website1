baton.pass() reference

The JavaScript API. One function, two optional arguments, one boolean back.

Once the embed script has loaded, it defines window.baton. It has one method.

Options

OptionTypeWhat it does
ctxstringThe artifact your tool just produced, such as "pdf" or "transcript". Optional.
targetElement, selectorWhere the card should be mounted. Optional; without it the card appears according to data-position.

ctx

ctx is one of the artifact ids from Picking inputs and outputs. It narrows the match: if your tool lists pdf and image as outputs, passing ctx: "pdf" tells Baton this particular success moment ended with a PDF, so the card is for tools that take one.

Without ctx, Baton considers all of your tool's outputs. You can also set a default for the whole page with the data-ctx attribute; a ctx passed to pass() wins.

target

Pass either a DOM element or a CSS selector:

The card is drawn inside a Shadow DOM, so your page's CSS can't break it and it doesn't leak into yours. See theming.

Return value

pass() returns a promise for a boolean:

Resolves toMeaning
trueA card was found and shown.
falseThere is no match right now. Nothing was shown, and nothing else happens.

false is not an error. It is the normal answer whenever no tool fits the journey, every fitting tool is a competitor or is out of credits, or the visitor has hit a fairness limit. Use it if you want to show something of your own in the same spot:

When to call it

Call pass() at the success moment, once per success:

  • After the file has been compressed and the download is available.
  • After the transcript has rendered.
  • After the export finished, not while it is running.

Avoid calling it on page load, on errors or in a loop. A card is worth showing when the person has just got what they came for.

The script is loaded with async, so window.baton can be undefined for a moment. Guard with optional chaining:

Under the hood

pass() asks the public card endpoint for a match using your site key and ctx, and renders the answer. If you would rather build your own card UI, you can call that endpoint yourself.
