There are two kinds of endpoint:

- The **card endpoint** is public. It uses your public site key (`bk_…`) and is what the embed
  calls. Use it to build your own card.
- The **account endpoints** under `/api/v1` are private. They use an API key (`sk_…`) and act as
  your account.

## Get a card

```http
GET https://toolbaton.com/api/baton/v1/card?key=bk_…&ctx=pdf
```

| Parameter | Required | Description                                                                 |
| --------- | -------- | --------------------------------------------------------------------------- |
| `key`     | yes      | The public site key of the host tool, the one where the success moment happens. |
| `ctx`     | no       | The artifact this moment produced, such as `pdf`. See [inputs and outputs](/docs/network/inputs-and-outputs). |

### 200: a card

```json
{
  "card": {
    "title": "Sign it in a minute",
    "body": "Add your signature and send it back.",
    "cta": "Open",
    "tool": { "name": "Example Sign", "host": "sign.example.com" },
    "via": ["PDF"],
    "href": "https://toolbaton.com/r/<token>"
  },
  "badge": true,
  "poweredBy": "https://toolbaton.com/makers?ref=card"
}
```

The values above are placeholders showing the shape.

| Field            | Meaning                                                                         |
| ---------------- | ------------------------------------------------------------------------------- |
| `card.title`     | The headline of the card.                                                       |
| `card.body`      | One line of supporting text.                                                    |
| `card.cta`       | The button label.                                                               |
| `card.tool`      | The tool being recommended: its `name` and the `host` of its website.           |
| `card.via`       | Labels of the artifacts that connect the two tools, for example `["PDF"]`.      |
| `card.href`      | A signed `/r/<token>` link. **Always link to this**, never to the tool directly. |
| `badge`          | `true` when the card should show the "passed by Baton" mark (hidden on paid plans). |
| `poweredBy`      | Where that attribution points.                                                  |

### 204: no match

When nothing fits the journey, the endpoint answers `204 No Content` with an empty body. Show
nothing, or something of your own. This is the same case where
[`baton.pass()`](/docs/embed/pass) resolves to `false`.

### Other statuses

| Status | Meaning                                                              |
| ------ | -------------------------------------------------------------------- |
| `400`  | The `key` is missing or malformed.                                   |
| `404`  | No active tool has that key (unknown, deleted or paused).            |
| `429`  | More than 60 requests a minute from one address. See `Retry-After`.  |

### Clicks

`card.href` is a signed redirect. It checks the signature, applies the
[fairness rules](/docs/network/fairness), moves credits if the click qualifies, then sends the visitor
to the tool with `?ref=baton` added. Linking anywhere else means the click isn't counted and the
credit isn't earned.

<Callout type="info" title="Building your own card">
  If you render the card yourself, show the Baton attribution (`badge` and `poweredBy`) unless
  your plan lets you hide it, and don't cache responses for long: a card is chosen for the
  moment it is requested.
</Callout>

## Account endpoints

These are authenticated with an API key you create at **Settings, API keys**. The key is shown
once when you create it and only its hash is stored, so copy it straight away.

```bash
curl https://toolbaton.com/api/v1/tools \
  -H "Authorization: Bearer sk_…"
```

| Endpoint         | Scope  | What it returns                                                         |
| ---------------- | ------ | ----------------------------------------------------------------------- |
| `GET /api/v1/tools` | `read` | The tools on your account, with credits and site keys. Studio plan. |
| `GET /api/v1/stats` | `read` | Credits, passes sent and received, cards shown, and a daily series (`?days=`, clamped by plan). Studio plan. |
| `GET /api/v1/me` | `read` | The account the key belongs to. Every plan.                             |

A key has scopes. `read` reads your account data and `write` creates and changes it. A request
outside a key's scopes is refused with `403`.

### Response shape

Successful responses wrap the result in a `data` key:

```json
{ "data": { } }
```

### Errors

Errors are [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) `application/problem+json` documents:

```json
{
  "type": "about:blank",
  "title": "Unauthorized",
  "status": 401,
  "detail": "Use `Authorization: Bearer <key>`."
}
```

| Status | Meaning                                              |
| ------ | ---------------------------------------------------- |
| `400`  | The body isn't valid JSON.                           |
| `422`  | The query or body failed validation.                 |
| `401`  | No key, or a key that isn't valid.                   |
| `403`  | The key lacks the scope, or the endpoint needs Studio. |
| `404`  | The thing you asked for doesn't exist.               |
| `429`  | You have hit the rate limit.                         |

### Rate limits

Each key gets **60 requests per minute**. Responses carry standard `RateLimit-*` headers, and a
`429` includes `Retry-After` with the number of seconds to wait.

<Callout type="warning" title="Keep keys server-side">
  API keys act as you. Never put one in browser code. The site key (`bk_…`) is the only key that
  belongs in a page.
</Callout>
